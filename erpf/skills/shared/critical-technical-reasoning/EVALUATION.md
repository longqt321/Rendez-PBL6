# Evaluation Rubric: Critical Technical Reasoning

| Dimension | Level 1: Novice / Fail | Level 2: Competent / Pass | Level 3: Exemplary / Proficient |
| :--- | :--- | :--- | :--- |
| **1. Assumption Detection** | Accepts document claims at face value; focuses only on formatting or grammatical details. | Identifies obvious assumptions regarding scale, infrastructure, or timeline. | Systematically uncovers hidden cognitive, architectural, and operational assumptions. |
| **2. Pre-Mortem Rigor** | No failure analysis performed, or lists trivial issues (e.g., "someone might make a typo"). | Sketches a plausible failure scenario with a clear root cause. | Detailed failure cascade walkthrough with trigger events, propagation paths, and blast radius mapping. |
| **3. Falsifiability & Evidence** | Uses subjective opinions ("I don't like this framework") without factual backing. | Points to concrete historical data or known failure modes in similar architectures. | Designs precise empirical probes and metric thresholds that would disprove the proposal's core thesis. |
| **4. Constructive Alternatives** | Merely rejects the proposal, leaving the team blocked without a viable path forward. | Suggests a simpler alternative or scaled-down version of the proposal. | Delivers a nuanced trade-off matrix with clear compromise architectures and concrete escape hatches. |
